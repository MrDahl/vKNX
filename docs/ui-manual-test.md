# Manual test list for the redesigned control panel

These steps need Windows, the installed program and ETS; they were **not** run by the developer (only the browser tests described in `limitations.md` were).

1. Start vKNX. The window opens in the *light* theme, with *Installation* selected. (If you chose the dark theme earlier, it stays dark.)
2. **Window sizes:** maximise, then make the window as small as Windows allows. All three workspace buttons, the cog and the theme button must stay visible. Try Windows scaling 125 % and 150 %.
3. **Add device:** *Add device* → pick *Dimming actuator* → keep or change the name → *Add device*. Try a name with a space or an existing name: you should get a clear message.
4. **Programming:** select the device, press *Programming button*. The red indicator and the text "Programming mode is ON" appear. In ETS, assign the physical address; the indicator goes out and the address shows in the details.
5. **Download from ETS:** the status chip changes from *No address* to *No application* to *Ready*. Check that *Download* in the details says "Complete".
6. **ETS parameters / objects:** the details list the parameters ETS wrote and the group addresses per object. The *Group addresses* chips jump to the Monitor.
7. **Simulation:** operate a button; the lamp card follows. Move the slider card while the dimmer card is changing: neither must jump. Hold a push-button key set to relative dimming (long press) and release.
8. **Telegram monitor:** open it under the simulation (*Telegram monitor*), drag the divider to resize, hide it again. In *Monitor*: filter on one device, on one group address, *Pause* while pressing buttons (the counter shows new telegrams), *Resume live*, *Clear view* (the file `vknx.log` in the data folder must be unchanged).
9. **ETS group monitor next to vKNX:** values shown for known DPTs must match ETS; an address no device uses shows "Unknown DPT" and raw data.
10. **Floor plan:** *Floor plan* → *Edit plan* → upload an image → place symbols, drag, rename in the properties panel → *Operate*. Quit and restart vKNX: the placements must still be there. Press symbols; the ⓘ button must open details without operating.
11. **Connection status:** click the status button in the header. With ETS connected to the vKNX interface it should list the connection; with ETS closed it should say none is connected. (This is the one thing the developer could not check against real ETS.)
12. **Connection loss:** close the vKNX background process from Task Manager while the window is open: a red banner appears and values dim. Start vKNX again; the window recovers or must be reopened.
13. **Existing data:** start the new version with the `data` folder of version 0.3.1 (devices, floor plan): devices and placements must appear unchanged.

## Added in 0.7.7 (diagnostics, start guide, livelier cards) - not run against real ETS

13. **Status strip (Installation):** connect ETS; the strip must say "ETS connected · 1 connection". Set ETS' interface address to a line other than the one of an addressed device (or set the vKNX interface line in Settings): the strip must name the device and the line and offer a fix. Give two devices the same address (not possible from ETS in one project; use two ETS projects): a duplicate warning must appear.
14. **"Device does not respond" hints:** in ETS try to address a device with its programming button off: the hint "ETS tried to give <device> an address, but the programming button was not pressed" must appear within a few seconds. Read an address no vKNX device has: "ETS is talking to <address>, but no vKNX device has that address".
15. **Setup checklist and last ETS action:** during a download the steps tick off one by one; the line "Last ETS action" must show the download ("Download: 4 of 4 parts written ...", or "Partial download ..." for a partial one). The lock box on secure devices must show "Secure commissioned" after the secure download, and the secure badge must turn green.
16. **Monitor:** after a secure download operate a secure input: the telegram must show the lock and "Encrypted · <device> accepted". *Explain this telegram* must give a sensible sentence for group writes, ETS services and secure telegrams. The filter "Encrypted (Data Secure) only" must hide all plain telegrams. (The recognition of secure telegrams is based on the telegram format; whether it matches what ETS shows for the same telegram has to be compared in the ETS group monitor.)
17. **Look:** Settings → Appearance: Light, Dark, Paper, Normal and Large. In Large the text and buttons must stay readable on a projector without cut-off texts.

## Added after 0.7.8 (data and cleanup) - Windows behaviour not tested by the developer

18. **Settings → Data and cleanup:** sizes must match the files in `%LOCALAPPDATA%\vKNX\data` (logs, `*_EC*.state` backups, plan). *Delete logs* must empty `vknx.log` and `console.log` while vKNX runs (this has only been tested on Linux: on Windows the open `console.log` must be emptied, not fail). *Delete backups* removes the `_EC` files and nothing else.
19. **Start a new installation:** with addressed devices and a secure commissioning done, the button must show the warning, and after confirming all devices must be at 15.15.255 with no download; secure devices must show a new certificate. In ETS the old project no longer matches (new FDSK): add the devices again. With the checkbox the floor plan is gone too, without it the plan and placements stay.
20. **Log limit:** make `vknx.log` larger than 10 MB (copy text into it while vKNX is closed) and start vKNX: the old file must be `vknx.log.1` and a new small `vknx.log` must exist.

Choose an icon for an output: card, device list and floor plan must show it at once; an icon with an "off" variant must change between on and off, other icons must look dimmer when off. **Reset** and "Use the built-in icon" bring the original back.

Restart vKNX: the icons must still be there (`icons.json` in the data folder). Remove the device: its icons must be gone from `icons.json`. ## Added after 0.8.0 (scenes, slider status) - ETS import and Windows not tried by the developer

Developer tests (in-process mini-ETS, `SceneTest`) cover call, store and learn of scenes, the key function, the slider status and the short old parameter area. They do NOT prove that ETS accepts the new product file.

31. **Import the new product file in ETS** (application version 4): the import must succeed without errors; in an existing project update the devices to the new version. Check that the push button key function list contains **Scene** and that the actuators show four scene slots per output/channel.
32. **Scene call:** set key 1 of the push button to *Scene 1*, set an output of the switch actuator to scene number 1 / state On, link the key's scene object and the actuator's Scene object to the same group address, download both: pressing the key must switch the output on and the card shows "Scene 1 called".
33. **Scene store:** set the key to *long press stores the scene*, switch the output manually, long-press the key: the card shows "Scene 1 stored". Change the output, short-press the key: the stored state returns. After a new ETS download the original ETS value applies again.
34. **Dimming actuator:** the same with a channel and brightness in %; the bar must jump to the value, and the status objects must follow.
35. **Secure variants:** the same with secure push button and secure switch actuator after commissioning with a FDSK (scene telegrams are then secure telegrams).
36. **Slider push:** link the new switch status object to the group address of a switch actuator output: switching the output from another key must light the lamp on the Press button; *Follow switch status object = No* must ignore it.
37. **Switch actuator card** with all 8 outputs enabled: nothing is cut off at the right edge, also in a narrow window.
38. **Keep in a scene slot:** set a switch actuator slot to *Keep the current state* and a dimming actuator slot to *Keep the current brightness*; calling that scene must leave those outputs/channels as they are while other slots of the same scene number still change.
39. **Check the application version in ETS** after the import (4) and that the key function **Scene** and the scene slots (Output n / Channel n pages) appear.

40. **Slider push button:** switch *Scene key* to Yes in ETS, set scene number and link object 5; after the download the card shows a Scene button; a short press calls the scene, with *Long press = stores* a long press stores it.
41. **Info display in ETS:** import `vknx-info-display.knxprod`, add the device, enable screens and set row types on the pages "Screen 1" ... "Screen 5"; for each row only the group object of the chosen type may appear (1 bit, 1 byte or 2 byte). Link rows to the status objects of an actuator, the multisensor and a scene group address, download.
42. **Info display card:** the rows show the values (On/Off, %, Scene n, temperature ...); *Previous/Next* page through the enabled screens (disabled screens are skipped); a row without a value yet shows a dash; after a restart of vKNX the status rows fill in again by themselves (Read on init; the group address must be answered by a device that has the Read flag, e.g. the status objects of the actuators and the multisensor).
43. **Info display paging over the bus:** link "Next screen" to a push button key (switch function) and press it: the card must show the next screen.

## Added after 0.9.1 (logic module and time master) - ETS import and Windows not tried by the developer
44. **Logic module in ETS:** import `vknx-logic.knxprod`, add the device. At first no input/output group objects may be listed. On the pages "Inputs 1-8" etc. switch some inputs/outputs on and type names: only those objects appear (object texts "Input n", "Output n"). The pages "Date and time" and "Timer 1" ... "Timer 8" must open without errors.
45. **Logic editor:** after the download, the card of the logic module shows the enabled inputs/outputs with names and **Open logic editor**. Place an input, a NOT or AND gate and an output, wire them, **Save**. The editor cannot be opened from anywhere else (no menu, no URL in the UI). Leaving with unsaved changes asks first.
46. **Logic over the bus:** link a push button key and an input (group address A), an output and a switch actuator output (group address B). Pressing the key must switch the actuator through the circuit (also inverted with NOT). Save, download again in ETS and restart vKNX: the circuit is still there.
47. **Delay, stairway, impulse, clock:** try each element with a push button and a lamp; the live values in the editor change colour while it runs.
48. **Time master:** set *Time and date objects* to "Date and time, one object" (and to the other modes), link the object to the info display or watch it in the monitor: time/date must be decoded correctly; "Send time now" and the cyclic interval work; set the clock to a weekday and speed 60x to see the timers fire.
49. **Weekday timers:** enable timer 1 with the weekdays Monday-Friday, on 07:00 and off 22:00, link the object to a lamp: on a Saturday on the simulated clock it must stay off.

## Added after 0.10.2 (binary input, thermostat, heating actuator, weather station, alarms) - ETS import and Windows not tried by the developer
50. **Import the six changed/new product files** (`vknx-binary-input`, `vknx-thermostat`, `vknx-heating-actuator`, `vknx-weather-station`, and the changed `vknx-multisensor` and `vknx-blind-actuator`) and check that ETS accepts them. Remove the old multisensor/blind actuator from the catalogue first if ETS complains. Report the exact ETS message if something is refused (new for ETS: DPT 20.102, 1.019, 1.005, a signed 16 bit parameter, enumeration values up to 240).
51. **Multisensor (the bug report):** set the temperature to 20 degrees (and tenths 0) in ETS, download: vKNX must show 20.0 (before: 2.0). Set random between 20 and 31: all values between 20.0 and 31.0, with decimals. Re-enter parameters that were stored in an old project (215 = 21.5 is now out of range).
52. **Top bar:** make the window narrower (below 600 px the tabs show only icons, version hidden); nothing may run out of the window, down to about 320 px.
53. **Binary input:** hold the large button of input 1 (Switching, closing = on, opening = off): the lamp must go on while held and off on release; the small button closes and opens it for good. Try Closing = Toggle with Opening = Nothing, the Dimming and Blinds functions (short and long press) and cyclic sending (monitor).
54. **Thermostat + heating actuator:** link thermostat *Heating control value* to valve 1 *control value*. Simulated room at speed 60 times: the valve opens, the room warms up past the setpoint, the valve closes, the temperature falls and the valve opens again (two-point). Switch the thermostat to *Continuous PI* and the valve to *Continuous 0-100 %*: the valve pulses open for part of every cycle.
55. **Thermostat keys and objects:** the mode keys change the setpoint (comfort/standby/economy/protection); the +/- keys shift it by 0.5 K up to 3 K; link a window contact (for example a binary input) to the window object: opening it must switch to building protection. Link the multisensor temperature to *External temperature sensor* with *Room temperature comes from* = external.
56. **Heating actuator monitoring:** set *Monitor the control value* to 5 minutes and an emergency position of 40 %: after five minutes without a control value the valve goes to 40 % and the alarm object (object 19) is sent; a control value ends it. Check a normally open valve: the drive is energised while the valve is closed.
57. **Weather station + blind actuator (awnings):** link *Wind alarm* of the weather station to *Wind alarm* of the blind actuator (and *Rain alarm* to *Rain alarm*). Set the wind to random 0 to 20 m/s with the threshold 12: when the alarm comes on the blinds set to *Moves up (retracts)* move up and are locked (the card says so; Move/Stop from a key is ignored, the monitor/log says why); when it ends the blinds stay and can be used again. Check the hysteresis (the alarm ends only below threshold minus hysteresis) and the rain alarm.
58. **Alarm monitoring:** set *Monitor the wind alarm* to 5 minutes on the blind actuator and stop the weather station (remove it or disable the alarm): after five minutes the card shows the wind alarm as active ("station silent") and the blinds retract.
